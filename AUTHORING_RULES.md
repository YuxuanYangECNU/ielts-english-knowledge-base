# Knowledge Base Authoring Rules · 知识库写入规则

> [!IMPORTANT]
> **Read this file before adding or rewriting any learning content in this repository.**  
> 在向知识库新增、整理或重写内容前，优先阅读本文件。

This document records the user's preferred way of building the entire IELTS knowledge base. It applies to **all sections**, not only Speaking.

## 1 · Core principle · 核心原则

**Curate, do not dump.** The purpose of this repository is to extract the most useful, reusable English—not to archive every question, page, screenshot or textbook item.

Before adding anything, ask:

- Is it genuinely useful for IELTS or everyday English?
- Is it worth active learning rather than simple recognition?
- Can it improve how the user actually understands, says or writes English?
- Does it add something new instead of repeating existing notes?

If not, leave it in the conversation.

> **Study material is a source, not an import instruction.** A photographed page or uploaded material should be filtered aggressively. Never copy an entire page simply because it was provided.

## 2 · Priority order · 写入优先级

When instructions conflict, follow this order:

1. **The user's explicit instruction in the current conversation**
2. **This file — `AUTHORING_RULES.md`**
3. The relevant category `README.md`
4. Existing templates and older note conventions

Before writing:

1. read this file;
2. read the relevant category page;
3. inspect the existing related note;
4. update an existing note when possible instead of creating duplicates.

## 3 · Style · 整体风格

- **English-first**, but not English-only.
- Use **Chinese headings, quick glosses or short notes** when they make scanning and review easier.
- Keep pages **clean, compact and logically grouped**.
- Prefer tables or short structured sections when they improve scanning.
- Do not create sections just to fill a template.
- Do not repeat the same explanation in several places.
- One item has one primary home; use links for cross-skill connections.

The repository should feel like a **high-value personal study map**, not a textbook and not a dictionary.

## 4 · Teach use, not definitions · 重点是“怎么用”

A definition alone is rarely enough.

For useful vocabulary or phrases, prefer:

**word / phrase → quick meaning → natural collocation or sentence pattern → how the user can use it**

For example, do not stop at:

> **reliable** = 可靠的

Prefer to connect it to a usable pattern such as:

> **I'd describe ___ as quite reliable because...**

The goal is to move from **recognition → usable language**.

## 5 · Personal language first · 优先用户自己的表达

When the user provides a real opinion, relationship, experience or sentence:

- use it before generic textbook examples;
- help the user write or say the sentence first when appropriate;
- correct and improve it into natural Band-7-level English;
- mark the refined result with **★** when useful;
- keep personal content only when it has learning value;
- do not invent personal facts or stories.

Generic examples are secondary. Add only a few when they teach a useful pattern the user's own examples have not covered.

## 6 · Speaking · 口语写入原则

Speaking is **sentence- and pattern-driven**, not vocabulary-dump-driven.

### Default learning workflow · 默认学习流程

For each new IELTS Speaking topic, use this sequence unless the user explicitly asks for something different:

1. **Study material first · 先看讲义**  
   The user sends photos or pages from the study material. Read them as source material, not as content to copy wholesale.
2. **Curate vocabulary · 提炼词汇**  
   Select only the vocabulary and phrases genuinely worth learning. Group them clearly by function or meaning and mark priority when useful.
3. **Learn patterns one by one · 逐条学习句式**  
   Introduce one useful Speaking pattern at a time rather than presenting a large block of ready-made answers.
4. **User produces first · 用户先造句**  
   Ask the user to make their own sentence with that pattern and the topic vocabulary.
5. **Correct and upgrade · 修改与提升**  
   Improve grammar, naturalness, precision and IELTS suitability. Explain only the changes that are genuinely useful for future speaking.
6. **Store the refined sentence · 沉淀个人表达**  
   Put the improved personal sentence directly under the matching pattern and prefix it with **★**.
7. **Then extend · 再挑战长句 / 长回答**  
   After several core patterns are usable, move from one-sentence production to longer answers using a simple development structure such as **description → reason / behaviour → example**.

The teaching order matters: **input → selection → controlled production → correction → personalisation → expansion**.

Do not skip directly from textbook vocabulary to long model answers. The goal is to teach the user how to build natural answers themselves.

### Topic pages

Use a simple flow:

1. **核心词汇 / Core vocabulary** — grouped logically, only high-value items.
2. **核心句式 / Speaking patterns** — several natural ways to express the idea.
3. **回答展开 / Answer development** — a compact way to turn a word into a fuller answer when useful.
4. **补充表达 / Extra useful expressions** — only language not already covered and genuinely worth learning.

For people topics, for example, separate:

- relationship terms;
- personality adjectives;
- relationship / behaviour expressions;
- reusable sentence patterns.

### Put priority levels in one table

When one vocabulary group contains both active-learning and recognition-only items, **keep them in one table** instead of splitting them into separate sections.

Use a compact priority marker, for example:

- **★** = priority / active mastery
- **○** = recognition is enough

This keeps the logic visible without making the page longer.

### Personal expressions belong inside the relevant pattern

Do **not** create a separate large **My expressions** section when the sentences naturally belong under existing Speaking patterns.

Instead:

- place the user's refined sentence directly below the matching pattern;
- prefix that sentence with **★**;
- use unmarked examples only as concise reference examples.

This lets the user see the pattern and their own usable sentence together.

### Sentence patterns matter more than isolated phrases

Do not store a long block such as:

> be close to someone = ...  
> get along with someone = ...  
> look up to someone = ...

without showing how they become answers.

Prefer patterns such as:

- **I'd describe ___ as ___ because...**
- **What I like most about ___ is that...**
- **One thing I really admire about ___ is...**
- **He/She is the kind of person who...**

Then connect vocabulary to them.

A useful answer-development structure is:

**person / relationship → description → reason or behaviour → small example**

Do not create rigid memorised full answers.

## 7 · Vocabulary & expressions · 词汇与表达

Do not build isolated word lists.

Prioritise:

- high-frequency or high-transfer vocabulary;
- collocations;
- useful chunks;
- easily confused distinctions;
- word families only when they improve actual use;
- natural spoken or written patterns.

Use a short Chinese gloss for fast review when helpful, followed by precise English usage.

Rare or low-value terms may be marked **Recognition only** rather than treated as active vocabulary. When they belong to the same lexical group as priority items, prefer **one table with a priority marker** rather than separate sections.

## 8 · Grammar & corrections · 语法与纠错

Store grammar only when it improves real usage.

Prefer:

**real question / mistake → compact rule → natural correction → reusable pattern → new example**

For the Personal Error Log:

- record repeated or high-impact language errors;
- merge recurring errors into one evolving pattern;
- **do not treat obvious typing mistakes as language errors**;
- silently correct clear input typos before storage unless the typo itself matters for learning.

## 9 · Reading · 阅读

Focus on transferable reasoning, especially paraphrase and TF/F/NG logic.

Prefer:

**verified source → relevant source sentence → question statement → paraphrase / logic change → evidence boundary → answer reasoning**

Do not copy large passages unnecessarily.

Keep source labels accurate. Never call material Cambridge IELTS unless the source is confirmed.

## 10 · Listening · 听力

Organise language by **scenario and listening value**, not by alphabetical word lists.

Prioritise:

- words the user failed to recognise;
- spelling or pronunciation risks;
- scenario vocabulary;
- signposts and distractors;
- useful contrasts that help recognition.

Group related items, for example:

**room types → house areas → facilities → requirements → security**

When the user supplies a list of correct answers, assume the intended meanings are correct unless there is a genuine semantic issue. Fix obvious typing errors directly rather than logging them as mistakes.

## 11 · Writing · 写作

Prioritise **precision, conditions of use and argument function** over decorative advanced vocabulary.

Separate:

- **Task 1** — description, comparison, trend language;
- **Task 2** — argument, cause/effect, concession, evaluation and development.

Prefer:

**function → useful expression → when to use it → natural example / argument extension**

Do not collect generic “high-level phrases” without explaining when they are appropriate.

## 12 · Review · 复习区

Review is smaller than the knowledge base.

Only add material that is genuinely worth active recall.

Use light statuses:

- **To practise**
- **In progress**
- **Usable**

Review should test production, not merely recognition.

## 13 · Source, privacy and accuracy · 来源与隐私

- Store the learning value, not the full conversation.
- Do not include unnecessary names, contact details or private information.
- Do not invent personal stories, opinions or relationships.
- Preserve source information when it matters for Reading, Listening or textbook material.
- Mark self-created material clearly when source identity matters.
- Keep the repository private.

## 14 · GitHub and Google Docs · 双端分工

- **GitHub** is the detailed master knowledge base.
- **Google Docs** is the compact companion for quick review and major takeaways.

Do not duplicate every GitHub detail into Google Docs. Sync only concise, high-value summaries.

## 15 · Before committing · 最终检查

Before adding or updating a note, confirm:

- Is this worth keeping?
- Is it concise enough?
- Is the logic easy to scan?
- Does it teach actual use?
- For Speaking, did the user get a chance to produce the sentence before a polished model replaced their effort?
- Have generic examples been replaced by the user's own language where available?
- Are personal sentences embedded beside the pattern they practise rather than isolated elsewhere?
- Are active and recognition-only words compactly distinguished without unnecessary extra sections?
- Did I avoid importing unnecessary textbook content?
- Did I check for overlap with existing notes?
- Are obvious typing slips corrected rather than misclassified as learning errors?

If the page becomes crowded, **delete before adding more**.
